# 异步通知实验（8.18）

异步信号和硬件中断的相似点与区别
相似点
都是异步发生的，不按当前程序顺序来
都会打断原来的执行流程
都需要后续处理函数来响应
都可以让当前任务暂时暂停，去处理更紧急的事
区别
中断：来自硬件或CPU内部事件，打断的是 CPU执行流
信号：来自内核或其他进程，作用在 某个进程
中断：进入内核中断上下文处理
信号：最终由进程在合适时机处理
中断：更底层，常见于设备响应
信号：更高层，常见于进程控制，比如 Ctrl+C、kill
sighandler_t signal(int signum, sighandler_t handler)
signum：要设置处理函数的信号。
handler：信号的处理函数。
返回值：设置成功的话返回信号的前一个处理函数，设置失败的话返回 SIG_ERR。
int (*fasync) (int fd, struct file *filp, int on)
fd：文件描述符，一般是用户态打开这个设备后的那个 fd
filp：对应的 struct file *，也就是这个打开实例
on：是否开启异步通知  1：开启，0：关闭
int fasync_helper(int fd, struct file * filp, int on, struct fasync_struct **fapp)
fasync_helper 函数的前三个参数就是 fasync 函数的那三个参数，第四个参数就是要初始化的 fasync_struct 结构体指针变量。
void kill_fasync(struct fasync_struct **fp, int sig, int band)
当设备可以访问的时候，驱动程序需要向应用程序发出信号，相当于产生“中断”。kill_fasync 函数负责发送指定的信号。
fp：要操作的 fasync_struct。
sig：要发送的信号。
band：可读时设置为 POLL_IN，可写时设置为 POLL_OUT。
返回值：无。
应用程序处理异步通知分三步
第一步，注册信号处理函数，使用 signal(SIGIO, sigio_signal_func);
其中 SIGIO 表示异步 I/O 信号，设备有数据或事件时内核会向应用程序发送这个信号；sigio_signal_func 是应用程序自己写的信号处理函数，收到 SIGIO 后就会进入这个函数，一般在里面调用 read() 读取设备数据。
第二步，设置当前进程为设备文件的属主，使用 fcntl(fd, F_SETOWN, getpid());
其中 fd 是 open() 打开设备文件后返回的文件描述符；F_SETOWN 表示设置这个文件描述符的信号接收者；getpid() 获取当前应用程序的进程 ID，意思是告诉内核：以后这个设备产生异步通知时，把信号发给当前进程。
第三步，开启异步通知功能，先用flags = fcntl(fd, F_GETFL);
 获取当前文件状态标志，其中 F_GETFL 表示读取文件状态标志；
再用 fcntl(fd, F_SETFL, flags | O_ASYNC); 
设置新的文件状态标志，其中 F_SETFL 表示设置文件状态标志，flags | O_ASYNC 表示在原有标志基础上增加异步通知功能。执行完这三步后，驱动里的 .fasync 函数会被调用，驱动会记录当前进程，后面设备事件发生时，驱动调用 kill_fasync()，应用程序就会收到 SIGIO 信号。
