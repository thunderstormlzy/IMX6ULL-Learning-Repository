# Linux SPI驱动（9.7）

**SPI实验问题总结**
**1. SPI是什么**
SPI是一种同步、全双工串行通信协议，常见连接线有：
- `SCLK`：时钟线，由主机产生
- `MOSI`：主机发送、从机接收
- `MISO`：从机发送、主机接收
- `CS/SS`：片选线，选择具体从机
主机拉低 `CS` 后，产生时钟。每产生一个时钟，主机和从机可以同时传输1 bit。
SPI通常是：
```text
同步通信 + 全双工通信
```
“同步”指通信双方使用时钟线配合，不是指“先发送还是同时发送”。
**2. SPI全双工是什么意思**
SPI硬件上同时存在发送和接收：
```text
主机发送一个字节的同时，也会接收一个字节
```
所以SPI发送多少个时钟，就会接收多少个时钟对应的数据。
但是，具体的从机协议可以规定：
- 当前阶段只发送
- 当前阶段只读取
- 发送的数据是否有意义
- 接收的数据是否有效
因此：
```text
SPI硬件始终可以收发
但从机协议决定哪些数据真正有用
```
**3. 只读时为什么还要发送数据**
SPI没有单独的“读取时钟”。主机想让从机发送数据，就必须提供时钟。
因此主机读取时，要发送一个没有实际意义的字节，例如：
```c
0x00
```
或者：
```c
0xFF
```
这个数据一般叫：
```text
dummy data，虚拟数据
```
它的主要作用是：
```text
占用发送过程，同时帮助主机产生时钟
```
例如：
```text
主机发送：0x00
从机返回：有效数据
```
虽然主机发送了 `0x00`，但从机在读取阶段会把它当作无效数据，重点是利用它产生的时钟把数据送出来。
**4. 只写时接收到的数据是什么**
只写操作时，从机仍然会通过 `MISO` 返回数据，因为SPI是全双工的。
但这时返回的数据可能是：
- 无意义数据
- 状态数据
- 上一次残留数据
- 从机协议规定的响应
如果当前只关心写入结果，主机可以直接忽略接收到的数据。
所以：
```text
只读：发送dummy数据，接收有效数据
只写：发送有效数据，接收数据通常忽略
```
**5. `spich0_readwrite_byte()`函数的作用**
```c
unsigned char spich0_readwrite_byte(
    ECSPI_Type *base,
    unsigned char txdata
);
```
参数含义：
```c
base
```
表示SPI控制器的寄存器基地址，用来指定使用哪个SPI控制器，例如：
```c
ECSPI1
```
```c
txdata
```
表示本次要发送的一个字节。
返回值表示SPI同时接收到的一个字节。
这个函数本身并不知道当前是“读”还是“写”。它实际做的是：
```text
发送一个字节，同时接收一个字节
```
到底属于读取还是写入，要由调用者和从机通信协议决定。
例如：
```c
spich0_readwrite_byte(ECSPI1, 0x9F);
```
如果芯片手册规定 `0x9F` 是“读取芯片ID命令”，那么它就是一次读命令。
**6. `0x9F`后面的数据为什么可能没有意义**
很多SPI芯片的通信流程是：
```text
发送读取命令
    ↓
发送寄存器地址或命令
    ↓
发送dummy数据产生时钟
    ↓
读取从机返回的数据
```
例如：
```c
spich0_readwrite_byte(ECSPI1, 0x9F);
spich0_readwrite_byte(ECSPI1, 0x00);
spich0_readwrite_byte(ECSPI1, 0x00);
```
其中：
- `0x9F`：告诉从机进入读取ID状态
- 后面的 `0x00`：主要用于产生时钟
- 接收端得到的返回值：才是有效ID数据
如果把 `0x9F` 改成其他数据，是否会写入，要看从机芯片手册：
- 可能被识别成另一个命令
- 可能被识别成寄存器地址
- 可能被识别成普通数据
- 也可能完全无效
不是SPI函数自动判断“无效数据不发送”，而是：
```text
数据实际上已经发送了，只是从机可能忽略它
```
**7. SPI和同步、异步通信的区别**
你的理解需要修正：
```text
同步通信
```
指通信双方有共同的时钟信号，SPI就是同步通信。
```text
异步通信
```
指没有单独的时钟线，双方提前约定波特率、数据位、停止位等，例如UART。
“同步”和“异步”不是：
```text
一边传一边收
或者两边一起传
```
SPI的完整描述是：
```text
SPI是同步全双工通信
```
UART通常是：
```text
异步通信
```
UART也可以同时收发，但它是否全双工和具体硬件有关。
**8. 为什么读写函数申请内存的大小不同**
如果读取 `len` 个数据：
```c
kzalloc(sizeof(unsigned char) * len, GFP_KERNEL);
```
因为只需要保存返回的 `len` 个数据。
如果写入函数需要先发送一个寄存器地址，再发送 `len` 个数据：
```text
第0字节：寄存器地址
第1到len字节：真正的数据
```
所以需要申请：
```c
sizeof(unsigned char) * (len + 1)
```
例如写入4个数据：
```text
寄存器地址 + 4个数据 = 5个字节
```
注意正确写法是：
```c
(unsigned char) * (len + 1)
```
这里容易混淆。真正的内存申请应该类似：
```c
buf = kzalloc((len + 1) * sizeof(unsigned char), GFP_KERNEL);
```
不能把 `(unsigned char)` 理解成申请空间。
由于：
```c
sizeof(unsigned char) == 1
```
所以也可以写成：
```c
buf = kzalloc(len + 1, GFP_KERNEL);
```
**9. `SPI_MODE_0`是什么意思**
```c
spi->mode = SPI_MODE_0;
```
表示SPI工作在模式0：
```text
CPOL = 0
CPHA = 0
```
通常表示：
- 空闲时钟电平为低电平
- 在第一个时钟边沿采样数据
- 另一个边沿改变数据
SPI常见有四种模式：
```text
模式0：CPOL=0，CPHA=0
模式1：CPOL=0，CPHA=1
模式2：CPOL=1，CPHA=0
模式3：CPOL=1，CPHA=1
```
具体使用哪种模式，要根据芯片数据手册设置。
**10. `spi_setup(spi)`有什么用**
```c
spi_setup(spi);
```
这个函数会根据 `spi`结构体中的配置，设置SPI控制器，例如：
- SPI模式
- 时钟频率
- 每个字多少位
- 片选方式
- 传输时序
通常应该检查返回值：
```c
ret = spi_setup(spi);
if (ret < 0) {
    return ret;
}
```
**11. `icm20608.private_data = spi`有什么用**
```c
icm20608.private_data = spi;
```
这相当于把当前SPI设备指针保存起来。
以后在驱动的其他函数中，就可以通过：
```c
icm20608.private_data
```
找到对应的SPI设备，然后进行读写。
可以理解为：
```text
把spi设备保存到驱动私有数据中，方便后续函数使用
```
**12. ICM20608读取时常见的地址处理**
很多SPI传感器会使用寄存器地址最高位表示读写方向，例如：
```c
读寄存器：reg | 0x80
写寄存器：reg & 0x7F
```
也就是说：
```text
最高位为1：读取
最高位为0：写入
```
但这不是SPI统一规定的，而是具体芯片的协议规定，必须看芯片手册。
因此，ICM20608读取流程通常类似：
```text
寄存器地址最高位置1
    ↓
发送寄存器地址
    ↓
发送dummy数据产生时钟
    ↓
接收寄存器数据
```
**13. SPI读取结果全是0时检查什么**
如果读取数据全部为0，优先检查：
1. `MISO`、`MOSI`、`SCLK`、`CS`是否接线正确。
2. 芯片是否正常供电，电压是否符合要求。
3. `CS`是否连接到了正确的片选。
4. 设备树中的SPI控制器是否打开。
5. 设备树中的 `reg` 是否对应正确的片选编号。
6. SPI模式是否正确，例如是否应该使用 `SPI_MODE_0`。
7. SPI时钟是否超过芯片允许范围。
8. 读取寄存器地址是否正确，是否需要加 `0x80`。
9. 是否正确发送了dummy数据。
10. 是否检查了SPI函数的返回值。
11. 是否完成了芯片复位、唤醒和延时。
12. 是否把Linux内核自动控制的片选和手动GPIO片选重复使用。
尤其要注意：
```c
spi_write_then_read()
spi_sync()
spi_sync_transfer()
```
这些函数的返回值必须检查。返回负数时，说明传输本身可能已经失败。
**14. Linux SPI实验和裸机SPI的关系**
裸机阶段通常是：
```text
直接操作SPI控制器寄存器
    ↓
配置时钟、模式、片选
    ↓
写发送寄存器
    ↓
读接收寄存器
```
Linux阶段通常是：
```text
SPI控制器驱动
    ↓
SPI核心层
    ↓
具体设备驱动
    ↓
spi_write、spi_read、spi_sync等API
```
所以Linux驱动一般不需要自己直接操作SPI寄存器，而是调用内核提供的SPI API。
**15. 最后整体记忆**
```text
SPI本质上是带时钟的移位寄存器通信。
每发送一个字节，就会同时接收一个字节。
只读时发送dummy数据，是为了产生时钟。
只写时接收的数据通常可以忽略。
SPI函数本身不判断读写，读写含义由从机协议决定。
写操作通常需要“寄存器地址 + 数据”，所以缓冲区可能是len+1。
读操作通常只保存返回数据，所以缓冲区大小通常是len。
SPI_MODE_0用于配置通信时序，spi_setup用于让控制器应用这些配置。
private_data用于保存SPI设备指针，方便驱动其他函数继续访问设备。
```
