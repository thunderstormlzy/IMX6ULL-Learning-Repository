# Linux多点电容触摸屏实验（9.9）

使用“
devm_
”前缀的函数申请到的资源可以由系统自动释放，不需要我们手动处理。
**Linux多点电容触摸屏实验问题总结**
1. **Type A和Type B有什么区别？**  
Type A只能报告当前帧的多个触摸点，不能准确追踪每根手指的连续移动；Type B通过`slot`和`tracking ID`管理每个触摸点，可以追踪手指从按下到移动、释放的完整过程。
2. **slot和触摸点ID有什么区别？**  
触摸点ID通常由触摸芯片提供，用来标识某根手指；slot是Linux input子系统中保存某个触摸点状态的位置。驱动通常根据ID选择slot，再把坐标写入该slot。
3. **`input_mt_slot(dev->input, id)`有什么用？**  
选择当前要操作的触摸点slot。后面的X、Y坐标和按下状态，都会归属于这个slot。
4. **坐标会不会保存在slot中？**  
会。调用`input_report_abs()`上报坐标时，Linux会把坐标记录到当前选中的slot中，并在同步时提交给用户空间。
5. **为什么设备树中既有`interrupt-gpios`，又有`interrupt-parent`和`interrupts`？**  
它们不是重复描述：  
`interrupt-gpios`描述触摸芯片连接的物理GPIO；  
`interrupt-parent`和`interrupts`把这个GPIO映射成Linux能够使用的IRQ中断号和触发方式。
6. **`reset-gpios`和中断GPIO有什么区别？**  
`reset-gpios`用于复位触摸芯片；`interrupt-gpios`用于触摸事件通知。GT9147启动时，INT引脚还可能参与I2C地址选择，因此初始化时会暂时改变它的输入输出状态。
7. **为什么通过IRQ确定地址？**  
这里容易混淆：I2C设备地址不是由Linux的IRQ号决定的。GT9147的I2C地址通常由复位期间INT引脚的电平决定；Linux中的`client->irq`只是触摸中断对应的IRQ号。
8. **为什么GT9147的设备结构体和普通字符设备不同？**  
因为它是I2C输入设备，不需要主设备号、副设备号和`cdev`。结构体主要保存GPIO、中断号、坐标范围、I2C客户端和`input_dev`等触摸设备信息。
9. **为什么复位流程中还要操作中断IO？**  
GT9147的INT脚不仅用于中断，还参与启动时的I2C地址选择。复位期间需要按照芯片要求控制INT电平，复位完成后再把它配置成输入中断脚。
10. **`reg >> 8`和`reg & 0xFF`有什么用？**  
GT9147寄存器地址通常是16位，需要拆成两个字节发送：  
`reg >> 8`取高8位；  
`reg & 0xFF`取低8位。
11. **为什么`touch_num = data & 0x0F`只取低4位？**  
状态寄存器的低4位表示触摸点数量，高位通常表示数据是否准备好或其他状态，因此用掩码只保留触摸点数量。
12. **为什么触摸ID也要使用`& 0x0F`？**  
触摸数据中的低4位保存触摸点ID，高4位可能是保留位或其他信息。使用`& 0x0F`可以只提取有效ID。
13. **为什么X、Y坐标要这样拼接？**
```c
input_x = touch_data[1] | (touch_data[2] << 8);
input_y = touch_data[3] | (touch_data[4] << 8);
```
触摸芯片把一个16位坐标拆成低字节和高字节保存，所以需要把高字节左移8位，再和低字节合并。
14. **`input_mt_report_pointer_emulation()`有什么用？**  
把多点触摸数据兼容模拟成普通单点指针事件，使一些只支持传统触摸事件的程序也能使用触摸屏。
15. **`input_sync()`有什么用？**  
表示一帧触摸数据上报完成，通知Linux input子系统统一处理刚才上报的触摸点、坐标和按键状态。
16. **为什么把GT9147的状态寄存器写成0？**
```c
data = 0x00;
gt9147_write_regs(dev, GT_GSTID_REG, &data, 1);
```
用于清除触摸芯片的数据准备标志，告诉芯片本次触摸数据已经读取完成，可以准备下一次触摸数据。
17. **`devm_request_threaded_irq()`的参数是什么？**  
第一个参数是设备对象；第二个是IRQ号；第三个是上半部函数；第四个是线程化中断处理函数；第五个是中断标志；第六个是中断名称；第七个是传给处理函数的私有参数。
18. **为什么有时最后一个参数传`dev`，有时传`&gt9147`？**  
它们代表传给中断处理函数的设备私有数据。`dev`通常是动态申请的设备结构体指针，`&gt9147`是某个全局结构体的地址。两者必须和中断处理函数中接收、转换的类型一致。
19. **`IRQF_ONESHOT`有什么用？**  
在线程化中断处理完成前，暂时屏蔽该中断，避免同一个中断反复进入，保证线程化处理过程不会被同一中断打断。
20. **`gt9147_read_firmware()`有什么用？**  
读取触摸芯片的产品ID和固件版本，并根据芯片信息设置最大X坐标、最大Y坐标和中断方式。它主要用于兼容不同型号的触摸芯片。
21. **如果硬件型号已经确定，可以删除固件读取函数吗？**  
可以手动固定相关参数，但不建议随意删除。只要驱动需要根据产品ID、固件版本选择配置，就应该保留；如果确定型号并正确填写所有参数，才可以简化。
22. **`get_unaligned_le16(&data[4])`是什么意思？**  
从`data[4]`开始读取两个字节，并按照小端格式组合成一个16位数，同时不要求该地址按2字节对齐。
23. **下面三句初始化有什么用？**
```c
gt9147.input->name = client->name;
gt9147.input->id.bustype = BUS_I2C;
gt9147.input->dev.parent = &client->dev;
```
分别设置输入设备名称、说明设备通过I2C总线连接，并建立输入设备与I2C设备之间的父子关系。
24. **`__set_bit()`设置了什么？**
```c
__set_bit(EV_KEY, input->evbit);
__set_bit(EV_ABS, input->evbit);
__set_bit(BTN_TOUCH, input->keybit);
```
声明设备支持按键事件、绝对坐标事件和触摸按键事件，使Linux知道该输入设备能够上报哪些类型的数据。
25. **`down = type != TOUCH_EVENT_UP`是什么意思？**  
只要触摸事件不是“抬起”，`down`就是`true`；如果事件是抬起，`down`就是`false`。也就是把按下、移动看作触摸有效，把释放看作触摸结束。
26. **为什么要把设备模式寄存器设置为0，把中断模式设置为1？**
```c
ft5x06_write_reg(&ft5x06, FT5x06_DEVICE_MODE_REG, 0);
ft5x06_write_reg(&ft5x06, FT5426_IDG_MODE_REG, 1);
```
前者让触摸芯片进入正常工作模式，后者配置触摸中断的触发方式，使芯片在检测到触摸数据后通知CPU。
**整个实验的核心流程：**
设备树描述I2C地址、复位GPIO和中断GPIO；驱动通过I2C读取触摸数据；根据触摸点数量读取每个触摸点的ID和坐标；选择对应slot；上报触摸状态和坐标；调用`input_sync()`提交一帧数据；最后清除芯片状态，等待下一次中断。
